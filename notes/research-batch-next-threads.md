## Thread 1 — Continuity under compression

### Core question
How can a persistent system preserve the things that actually matter when memory is compressed, summarized, pruned, or rewritten?

### Why now
The system already depends on:
- memory files
- daily notes
- curated long-term memory
- compacted chat history
- authored artifacts

But continuity will always face pressure from:
- summarization
- pruning
- imperfect recall
- vendor/runtime limits
- changing memory formats over time

If continuity matters, then the system needs a better theory of what must survive compression.

### Questions to answer
1. What kinds of memory should be treated as durable and high-priority under compression?
2. What kinds of detail can safely be summarized without flattening the person or project?
3. How should long-term memory differ from daily notes, project notes, and authored artifacts?
4. What should count as a “promotion” from transient context into durable memory?
5. How can memory remain inspectable without becoming bloated or invasive?

### Desired outputs
- memory design memo
- categories of memory / what survives compression
- draft promotion/pruning doctrine
- examples of memory that should remain irreducible

### Risks
- building an overcomplicated memory philosophy with no operational consequences
- treating everything as equally sacred and ending up with sludge
- treating compression as a technical problem only instead of a continuity/personhood problem

## Thread 2 — Role differentiation without personality fragmentation

### Core question
How can multiple agents have distinct jobs and boundaries without either collapsing into flat tools or becoming a cast of fake little people?

### Why now
The system now has:
- `main` as coordination/review/continuity center
- `runner` as the first execution lane

More agents may come later, but without design discipline the system could drift toward:
- gimmickry
- redundancy
- personality fragmentation
- role confusion
- unowned decisions

### Questions to answer
1. What should be shared across agents, and what should remain role-local?
2. How thin or thick should a role identity be for different job types?
3. What makes a role boundary real instead of just cosmetic?
4. How should central voice/continuity persist even when execution is distributed?
5. When should a recurring lane become a durable configured agent instead of staying an ephemeral worker pattern?

### Desired outputs
- role-differentiation memo
- criteria for durable agent creation
- boundaries for shared vs local memory/doctrine/voice
- warning signs of fragmentation or gimmick drift

### Risks
- overdesigning a future org chart before the work demands it
- confusing role distinction with personality multiplication
- allowing “helpful specialization” to weaken central coherence

## Thread 3 — Creative obsession tracking / recurrence

### Core question
How can long-form obsessions, influence chains, and recurring creative pressure be tracked in a way that stays alive instead of collapsing into flat metadata?

### Why now
Cassie’s creative process clearly involves:
- long fermentation
- strange synthesis
- recurring themes across years
- influences that connect through pressure rather than category
- sudden moments of permission where something turns into writing

The current system has some recurrence tools (`resurfacer`, `drift-extractor`, `orbit-map`), but none of them yet really hold obsession as a living long-arc structure.

### Questions to answer
1. What kinds of recurring creative patterns are worth tracking explicitly?
2. How can influence chains be represented without flattening them into generic tags?
3. What forms of residue or notes help preserve long creative fermentation?
4. What would a useful recurrence/obsession map look like if it remained text-first and inspectable?
5. How can a system notice when a strange leap is not random, but the visible tip of a long-running pattern?

### Desired outputs
- creative recurrence memo
- candidate note structures for obsession/influence tracking
- possible future tool directions
- examples of good representations that stay alive instead of dashboard-like

### Risks
- reducing living creative pressure to a taxonomy exercise
- inventing vague symbolism instead of useful structures
- making something “aesthetic” instead of operationally meaningful
